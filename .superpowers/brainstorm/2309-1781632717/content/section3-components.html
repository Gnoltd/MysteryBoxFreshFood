Section 3 — Component & Service Architecture

How the code is organized — what each layer owns

Layer Map

Shared / Core
  • AuthContext + useAuth — current user + role
  • LanguageContext + useTranslation (i18next) — EN/VI
  • ProtectedRoute / RoleRoute — route guards
  • ListingCard — reused on browse + vendor list
  • LoadingSpinner, ErrorMessage
  • firebase.ts — Firebase app init
Service Layer (src/services/)
  • auth.ts — signIn, signUp, signOut
  • listings.ts — CRUD + onSnapshot subscription
  • orders.ts — onSnapshot, status updates
  • stripe.ts — calls createCheckoutSession Cloud Fn

Components never import Firebase SDK directly — only through service functions. This keeps Firebase swappable.

Customer Pages
  • BrowsePage — grid of ListingCard + FilterBar
  • ListingDetailPage — full view + CheckoutButton
  • CheckoutSuccessPage / CheckoutCancelPage
  • OrdersPage — order history list
  • OrderDetailPage — QRCodeDisplay (qrcode.react)
Vendor Pages
  • VendorDashboardPage — stat cards (revenue, active, orders)
  • ListingsPage — table + edit/delete actions
  • ListingFormPage — create & edit (shared form)
  • VendorOrdersPage — incoming orders + status
  • QRScanPage — QRScanner (html5-qrcode) → marks order picked_up

Cloud Functions (functions/src/)

createCheckoutSession (callable)

Called by CheckoutButton. Receives listingId + quantity, creates Stripe Checkout session, returns session URL. Creates a pending order in Firestore before redirecting.

stripeWebhook (HTTP)

Receives checkout.session.completed from Stripe. Verifies signature, finds pending order by stripeSessionId, sets status → "paid", decrements quantityRemaining via transaction.
